# QQ 平台语音转写补丁（2026-10-31）

问题：QQ 语音附件的 `asr_refer_text` 已有转写时，旧实现仍先下载音频；下载因媒体域名校验失败时，将消息降级为文件段，转写标签可能被 Host 的正文重算覆盖。

修改：`plugin.py` 的 `_build_attachments` 在语音分支先验证并去除转写字符串首尾空白。有非空转写时直接生成 `[语音: 转写文字]` 文本段，不访问音频 URL、不调用额外 ASR。Host 的普通文本处理会保留该内容，并继续保留同条消息的原正文和其他附件。

无平台转写时，保留音频下载及文件降级逻辑；下载成功的语音段 `data` 改为空字符串，防止 `[语音]` 占位符被误判为已有识别结果。Host 是否执行 ASR，仍由现有开关和模型配置决定。

只修改插件源码与说明，未修改 MaiBot 核心、模型配置、媒体域名白名单、下载鉴权、重定向限制或出站语音功能。未部署本地 STT，也未修改 DSH。

验证：运行 `python -m pytest tests/test_voice_transcripts.py -q`。测试使用真实插件和 Mock gateway/下载函数，覆盖已有转写无需下载、语音 MIME、空白或无效转写、原始音频、下载失败、图片/文件、混合正文、多条语音，以及转写内容不作为管理命令执行。测试不连接 QQ、不发送消息、不调用模型 API。

适用条件：QQ 消息需实际提供非空字符串 `asr_refer_text`。没有平台转写时仍需可用的音频和 ASR。本修复不改变音频域名校验，也不保证所有语音都有平台转写；与音频附件域名支持是独立修复。
